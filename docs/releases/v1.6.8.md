# v1.6.8

## Highlights

- **Switch port IP/MAC observations:** the interface detail view can show MAC addresses learned on a switch port and IPv4 addresses correlated from ARP observations. VLAN and observation source are included to explain confidence; uplinks may show downstream devices and do not prove direct attachment.
- **WeCom self-built application notifications:** configure CorpID, AgentId, Secret and recipient UserIDs in Alert Center. Trigger and recovery notices use the existing notifier queue, with retries and delivery records. SMTP continues to work independently.
- **Topology link state:** an unreachable endpoint alone no longer marks an automatically discovered physical link as down. The UI reports it as unconfirmed until fresh port status or neighbor evidence is available.
- **Syslog correlation:** cast the source address to `inet` during device matching so PostgreSQL can compare it with the device host column without an `inet = text` operator error.
- **API dependency security:** update Fastify and its transitive JWT/URI dependencies to patched lockfile versions; `npm audit --omit=dev` reports no runtime dependency vulnerabilities.
- **Endpoint history retention:** configurable normal and emergency cleanup retention for IP/MAC observations is included in Linux and Windows Compose configurations.

## Database migrations

This release adds migrations `012_endpoint_observations.sql`, `013_wecom_app_notifications.sql`, and `014_ip_mac_observation_locations.sql`. Apply the bundled migrator before starting the updated API and collectors. Migration 014 retains observations for the same IP/MAC on separate VLANs or interfaces.

Back up PostgreSQL and deployment configuration first. Keep the existing PostgreSQL 18 data volume and Compose project name. Do not run `docker compose down -v` or reinitialize the database with seed data.

For an existing source deployment, follow [the online upgrade guide](../../deploy/upgrade-source-使用说明.md). The script defaults to v1.6.8 and preserves the existing data volume; read its prerequisites and limitations before running it.

## Verification notes

Port IP/MAC visibility depends on device SNMP views exposing Q-BRIDGE-MIB/BRIDGE-MIB and ARP tables. VLAN-less FDB or ambiguous duplicate MAC/IP observations are labeled with lower confidence. WeCom delivery requires outbound HTTPS access to `qyapi.weixin.qq.com` and a correctly configured application visibility scope.
