# v1.6.6

本版新增 Syslog 接收与检索功能，并完善系统日志页面的图标提示。PostgreSQL 主版本仍为 18；已有数据通过增量迁移保留。

## Syslog 收集与检索

- 新增独立 `syslog-collector` Go 容器，接收 RFC 5424 与常见 RFC 3164 UDP 日志，默认发布主机 UDP 514 端口。
- 新增 `011_syslog_events.sql`，保存来源地址、设备时间、设施/级别、程序信息、结构化数据和原始消息，提供全文搜索索引；日志默认保留 30 天并分批清理。
- API 提供鉴权保护的收集状态和事件搜索接口，支持关键词、设备、级别、时间范围和分页。
- 前端新增“系统日志”页面，提供收集器状态、严重/错误计数、设备与时间筛选、快捷级别筛选、日志表格、详情面板、自动刷新和当前页 CSV 导出。
- 日志页增加标题、统计、筛选、表格字段和详情元信息图标，便于快速辨识时间、设备、来源地址、程序与消息。
- 根 Compose、Windows 离线 Compose、环境变量模板和离线打包脚本均包含新的收集镜像。

## 协议和容量边界

当前只监听 UDP，不提供 TCP/TLS、磁盘缓冲或 Syslog 自动告警。UDP 可能丢包；内存队列和单条消息大小有上限，页面展示收集器丢弃计数。设备按来源 IP 精确关联；NAT 或代理后的源地址无法自动识别原设备。收集主机的防火墙需允许 UDP 514 入站，网络设备需配置对应的 Syslog 目标。

## 升级

升级前备份数据库、`.env` 和 Compose 配置，沿用原 Compose 项目名与 PostgreSQL 18 数据卷。不要执行 `docker compose down -v` 或 `seed.sql`。获取 v1.6.6 源码后，在原部署目录执行：

```bash
docker compose build
docker compose run --interactive=false -T --rm --no-deps migrator
docker compose up -d
docker compose ps
```

确认 migrator 成功后再开放设备发往主机 UDP 514 的 Syslog 流量。Windows 离线部署使用本 Release 对应的 `IMAGE_VERSION` 和八个容器镜像，并按部署说明执行安装与启动。
