# v1.6.10

## Highlights

- **Topology endpoint estimates:** topology device nodes show an estimated endpoint count based on recent switch FDB observations. Select a switch to inspect MAC, VLAN, port, interface alias, and candidate IPv4 addresses correlated from ARP observations.
- **Explainable endpoint exclusions:** recent LLDP/CDP network ports are excluded from terminal estimates. Ports learning 20 or more MAC addresses are listed as possible shared/AP ports instead of being counted as ordinary terminals. Counts use observations from the last 30 minutes; endpoint and IP totals are estimates, not guaranteed device inventory.
- **On-demand endpoint collection:** the topology detail panel can queue a device scan for neighbors, FDB, and ARP through the existing serialized collector queue. Unsupported tables, empty tables, failed scans, and stale data remain distinguishable.
- **Alert confirmation and health events:** CPU/interface alert rules support a sustained-condition duration. Interface-down alerts require administrative state to be up. Device health alerts distinguish confirmed unreachability from stale collection data while SNMP or Ping remains reachable; the legacy `device_no_data` rule is disabled by migration.
- **Manual event closure:** manually closed events are labeled separately. If the triggering condition persists, later collection can create a new active event.
- **Linux/WSL source upgrade:** the online upgrade script defaults to v1.6.10, checks the existing PostgreSQL 18 volume and Compose project, backs up the database before migration, and retains the old source directory and image tags for recovery.

## Database migration

Migration `016_alert_notification_policy.sql` adds alert-condition observation state and the event resolution source, seeds separate offline/collection-error rules, disables the legacy no-data rule, and assigns a default 60-second duration to existing CPU/interface rules that had no duration configured. It is additive and runs through the existing migrator.

The topology endpoint feature reuses the existing FDB/ARP observation and topology scan tables; it does not add a schema migration. Demo records used in local preview are not included in this release.

## Upgrade notes

Back up PostgreSQL and deployment configuration before upgrading. For a supported Linux/WSL source deployment using PostgreSQL 18 and a named volume, see [online upgrade instructions](../../deploy/upgrade-source-使用说明.md). The script does not upgrade PostgreSQL major versions and does not apply to the Windows offline bundle. Existing alert rules and notification channel configuration are retained.
