# Netlooker v1.6.2

本版修正设备列表将采集数据过期直接判为离线的问题，新增后台主动探测与连续失败确认。

## 状态判定

- 最近 6 分钟有采集活动显示在线。超过 6 分钟后，独立后台任务每 30 秒执行轻量 SNMP 探测，失败后执行三次 Ping；单任务预算 10 秒，最多并发 8 台设备。
- SNMP 或 Ping 成功显示采集异常；两者连续至少三轮失败且持续至少 60 秒，才显示红色离线。
- 探测无法执行或结果超过 90 秒显示状态未知。旧探测结果不会覆盖新的采集活动，配置变化和停用也会使旧结果失效。
- 首次采集前显示等待首次采集。设备列表每 30 秒刷新，状态提示显示采集时间、探测时间及原因。
- 采集器以非 root 用户运行，镜像新增 iputils，Ping 程序使用 NET_RAW 文件能力。

## 升级

本版继续使用 PostgreSQL 18，无需再次升级数据库主版本。迁移 `007_device_health.sql` 新增设备状态表，保留已有数据。

源码部署：先备份数据库并保留原 `.env`，获取标签后重建应用镜像：

```bash
git fetch origin --tags
git checkout v1.6.2
docker compose up -d --build
docker compose ps
```

若安装目录有本地修改，请先保存并合并配置，避免直接覆盖。不要执行 `docker compose down -v`。

本次 GitHub 发布提供版本标签、源码和发布说明；旧 v1.6.1 离线包不包含本版功能。可使用 `deploy/build-release.ps1 -ReleaseVersion 1.6.2` 从当前源码构建新离线包，不要将旧镜像重新命名冒充新版本。

## 验证与边界

已通过 Go 全包测试、竞态检查、go vet、PostgreSQL 状态确认和恢复集成测试、API 状态测试、Vue 类型检查与构建，以及 Docker 内 SNMP 响应、SNMP 超时后 Ping 成功、探测取消与退出码测试。Docker 健康检查、登录及经网页代理的设备 API 均通过。

SNMP 与 ICMP 同时被防火墙阻断时，仍可能判为离线；该状态表示监控端连续不可达，不证明设备断电。原有无数据邮件告警和端口流量过期规则保持独立。本版尚未验证百台设备容量或长时间运行稳定性。
