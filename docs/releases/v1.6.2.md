# Netlooker v1.6.2

本版修正设备列表将采集数据过期直接判为离线的问题，新增后台主动探测与连续失败确认。

## 状态判定

- 最近 6 分钟有采集活动显示在线。超过 6 分钟后，独立后台任务每 30 秒执行轻量 SNMP 探测，失败后执行三次 Ping；单任务预算 10 秒，最多并发 8 台设备。
- SNMP 或 Ping 成功显示采集异常；两者连续至少三轮失败且持续至少 60 秒，才显示红色离线。
- 探测无法执行或结果超过 90 秒显示状态未知。旧探测结果不会覆盖新的采集活动，配置变化和停用也会使旧结果失效。
- 首次采集前显示等待首次采集。设备列表每 30 秒刷新，状态提示显示采集时间、探测时间及原因。
- 采集器以非 root 用户运行，镜像新增 iputils，Ping 程序使用 NET_RAW 文件能力。

## 升级

本版继续使用 PostgreSQL 18，无需再次升级数据库主版本。迁移 `007_device_health.sql` 新增设备状态表，保留已有数据。

源码部署：先备份数据库并保留原 `.env`，获取标签后重建应用镜像：

```bash
git fetch origin --tags
git checkout v1.6.2
docker compose up -d --build
docker compose ps
```

若安装目录有本地修改，请先保存并合并配置，避免直接覆盖。不要执行 `docker compose down -v`。

离线发布附件：[netlooker-1.6.2-windows-amd64.zip](https://github.com/fansboyu/snmp/releases/download/v1.6.2/netlooker-1.6.2-windows-amd64.zip)，包含七个固定版本镜像、安装/启停、备份恢复脚本及迁移 SQL，大小 229,180,429 字节。目标电脑仍需预装 Docker 的 Linux 容器环境。包内不含真实数据库或本机账号配置。

SHA-256：`c9069ac58ec31cf66b847a1afb32b6c50586b3fc0a59143c10deb7eb6fb9436b`。同时提供 `.zip.sha256` 校验附件。旧 v1.6.1 离线包不包含本版功能。

离线包部署从 v1.6.1 升级：先在旧目录执行 `backup.ps1` 并停止应用，将新包解压到新目录，复制原 `.env`，仅将 `IMAGE_VERSION` 改为 `1.6.2`；保持 `COMPOSE_PROJECT_NAME`、数据库密码、JWT 密钥及端口配置。随后执行 `install.ps1`、`start.ps1`、`status.ps1`，使用原 PostgreSQL 18 数据卷完成迁移，无需重新恢复整个数据库。不要执行 `down -v`。

源码构建用户应继续沿用原 Compose 项目名，避免将目录名变化误当成新部署。本包的首次安装、状态集成测试和非 root Ping 已在 GitHub 构建环境验证；本地另完成 Windows PowerShell 5.1 导入、启动、重启及数据保留验证。本地独立构建 ZIP 的校验值可能不同，以上校验值仅适用于 GitHub 附件。

## 验证与边界

已通过 Go 全包测试、竞态检查、go vet、PostgreSQL 状态确认和恢复集成测试、API 状态测试、Vue 类型检查与构建，以及 Docker 内 SNMP 响应、SNMP 超时后 Ping 成功、探测取消与退出码测试。Docker 健康检查、登录及经网页代理的设备 API 均通过。

SNMP 与 ICMP 同时被防火墙阻断时，仍可能判为离线；该状态表示监控端连续不可达，不证明设备断电。原有无数据邮件告警和端口流量过期规则保持独立。本版尚未验证百台设备容量或长时间运行稳定性。

构建依赖审计提示 fast-jwt 6.2.4 存在公开漏洞报告。当前项目使用 HMAC 密钥，尚未确认报告中的特定配置攻击在当前用法下可触发；本包严格对应 v1.6.2 标签，未宣称相关依赖漏洞已修复。详情见 [公开漏洞报告](https://github.com/advisories/GHSA-ww5h-9m49-7xx4)。
