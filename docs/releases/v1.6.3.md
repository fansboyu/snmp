# v1.6.3

本版将此前本地拓扑增强与自动发现修复一起发布，应用版本从 1.6.2 升级为 1.6.3。PostgreSQL 仍为 18，不更换数据卷。

## 自动发现修复

- 拓扑页增加“发现诊断 / 立即采集”，展示启用、已尝试、成功、排队设备数量，有效证据、待确认邻居和端口映射不完整数量，并列出各设备协议结果、原因和时间。
- `POST /api/topology/devices/:id/scan` 返回 202，把单设备 LLDP/CDP 请求交给采集器；同一设备共用原有调度与工作池，避免与正常指标和邻居任务重叠。重复点击复用活动请求，完成后 30 秒内限制再次提交。
- 新增 `009_topology_discovery_requests.sql` 保存 pending/running/completed/failed 请求。采集器周期检查超时任务，运行超过 2 分钟或排队超过 10 分钟会标记失败；设备停用也会结束待执行请求。没有运行采集器时，页面将展示排队或超时提示。
- 只有短名称相同的设备不再直接认定为同一设备，显示候选并等待人工确认；此前仅靠弱匹配生成且未人工锁定的连接，会在同步时撤销，保留变更记录。
- 补充 Gi/GE、Te/XGE/10GE 等端口名规范化；名称不能匹配时只接受设备内唯一的 SNMP ifAlias，重复别名不自动选择。
- 部分证据只有在同一设备对、共享已知端口、另一端兼容且候选唯一时才补全并合并；不按设备对简单合并，保留真实并行连接。
- 修复本地 Docker 并行启动时复现的数据库初始化死锁：API 与 Go 服务使用同一事务级 advisory lock 串行执行运行时 DDL，并对 PostgreSQL 死锁执行有界重试；不吞掉认证、语法等其他错误。

## 一并发布的拓扑增强

`008_topology_monitor.sql` 增加协议快照、身份匹配、物理连接证据、人工绑定、位置锁定、人工聚合与变更历史。页面支持查看/编辑分离、稳定刷新、端口流量和告警详情、设备分组及自动布局预览，详见 [网络拓扑改造说明](../网络拓扑改造说明.md)。

## 更新部署

备份数据库、原 .env 和 Compose 配置，沿用原项目名与数据卷。不要执行 `down -v` 或 seed 初始化。获取本标签源码后执行：

```bash
docker compose build
docker compose run --interactive=false -T --rm --no-deps migrator
docker compose up -d
docker compose restart web-vue3
docker compose ps
curl --fail http://localhost:15173/health
```

已有设备、历史采样和邮件设置保留。迁移成功后再运行新 API 与采集器。测试在独立数据库进行，不把演示设备写入真实监控数据库。

## 使用边界

立即采集只读取已纳管并启用的设备，不扫描新网段，也不自动纳管未知邻居。排队请求不能绕过存储保护或同设备正在执行的任务。协议不可见、无邻居和超时有独立原因展示，不代表物理断线。自动拓扑依赖设备开放正确的 SNMP 视图及邻居数据；聚合仍由人工维护，不自动判断 LACP。

本 Release 的源码与标签包含上述改动；旧版本离线附件保持原样，新离线镜像包需基于 v1.6.3 标签另行构建。
