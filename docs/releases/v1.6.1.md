# netlooker v1.6.1

本版本更新 PostgreSQL 和应用基础环境，保留 v1.6.0 的端口流量、三列关注卡片、邮件配置及独立采集调度。

## 数据库与基础环境

- PostgreSQL 16 → 18，当前验证版本为 18.6。使用独立 postgres18-data 卷，挂载 /var/lib/postgresql；默认 PGDATA 为 /var/lib/postgresql/18/docker。采集器磁盘保护检查同一个新卷。
- 三个 Go 服务使用 Go 1.27.1 编译，运行基础镜像升级到 Alpine 3.24.2。
- API、迁移工具及前端构建使用 Node 24.21.0 / Alpine 3.24。
- pgx/v4 → pgx/v5 5.11.0；连接池改为 pgxpool.New，保留 Ping，维持启动时连接检查。旧 pgx/v4、pgproto3/v2 和不再需要的 x/crypto 依赖移除。
- gosnmp 更新到 1.45.0，x/text 更新到 0.42.0。
- API 依赖更新：Fastify 5.12.5、pg 8.23.1、CORS 11.3.0、JWT 10.2.2。Go 构建恢复默认模块校验。
- 新增 Linux SMTP 回归测试，验证 STARTTLS、隐式 TLS、拒绝缺少 STARTTLS 和未受信证书；测试邮件仅由本地服务器捕获。

## 离线部署

发布附件 netlooker-1.6.1-windows-amd64.zip 包含七个固定版本运行镜像、Compose、安装/启停脚本、备份恢复、旧备份转换、迁移 SQL 和部署说明。VERSION.json 记录 PostgreSQL 主版本、源码提交和镜像 ID；ZIP 附 SHA-256 校验文件。

目标电脑需预装 Docker Desktop 的 Linux 容器环境、Compose 2.20+。镜像安装和应用启动不需要公网拉取；SNMP 采集及邮件发送分别需要设备网络和 SMTP 连通。包内不包含 Docker/WSL 安装程序、生产数据库或真实账号配置。

## 从 v1.6.0 升级：必须迁移 PostgreSQL 数据

不能仅替换镜像或复制 .env 后直接 start.ps1，否则会使用新的空数据库卷。migrator 只处理表结构，不会升级 PostgreSQL 16 的数据文件。

1. 在旧发布目录停止应用写入，保留数据库运行：docker compose stop api-gateway web-vue3 collector-go discovery-worker notifier。
2. 在旧目录运行 backup.ps1，保存整个备份目录及旧发布包。随后运行 stop.ps1，保留旧 postgres-data 卷；不要执行 down -v。
3. 解压 v1.6.1 到新目录，将旧 .env 复制过去，设置 IMAGE_VERSION=1.6.1；保留 COMPOSE_PROJECT_NAME、POSTGRES_PASSWORD、JWT_SECRET 和端口配置。
4. 在新目录运行 install.ps1，再运行 restore.ps1 -BackupDirectory <旧备份目录>。恢复脚本会启动新 PostgreSQL 18 数据库、先备份目标数据库，再以事务恢复来源数据，并保留原 JWT 密钥。
5. 恢复完成后运行 start.ps1、status.ps1，核对账号、设备、端口、历史样本及邮件配置。关注记录保存在浏览器，不随数据库备份跨电脑同步。

已使用 PostgreSQL 18 和 postgres18-data 卷的本地交付版本，可保留原项目名和配置，备份后按普通同主版本流程升级。

源码部署用户见 docs/postgresql18-migration.md。涉及额外数据库角色或授权的环境需要单独迁移；当前项目使用 snmp 角色。

## 回退边界

保留旧包、旧卷和迁移前备份。新环境尚未恢复正式写入时，可停止新环境并用旧包及旧 postgres-data 卷回退。新库开始写入后，旧卷不包含新增数据；PostgreSQL 18 备份不保证可以恢复到 16，也不能用 16 镜像启动 18 数据卷。

## 验证

- Go 全包测试、竞态检测和 go vet；pgx v5 的 PostgreSQL 18 SCRAM、批量写入、Counter64 精度与回滚。
- 隔离 Docker SNMP→采集器→数据库→API→页面链路、发现任务、加密 JSONB 邮件配置及本地通知队列。
- SMTP STARTTLS/隐式 TLS 和证书拒绝测试，API 八项测试，Vue 类型检查和生产构建。
- 三个 Go 二进制漏洞扫描及 npm 审计均无报告；这不等同于覆盖所有镜像操作系统漏洞。
- Windows PowerShell 5.1 的离线镜像导入、首次建库、备份导入、跨项目恢复、重启和关注端口页面。

现网设备仍有 SNMP 超时，需要结合设备与网络排查；隔离测试设备的完整采集链路已通过。未进行百台设备容量压测，未启用 TimescaleDB，也未引入多采集器租约或数据库高可用。
