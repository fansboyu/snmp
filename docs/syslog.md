# Syslog 接收与日志检索

## 组件协作

```text
网络设备 -- UDP Syslog --> syslog-collector --> PostgreSQL
                                          ↑
浏览器 --> Vue 页面 --> Nginx --> API Gateway
```

`syslog-collector` 是独立 Go 容器，接收 RFC 3164 / RFC 5424 的 UDP 消息，按批次写入现有 PostgreSQL。它不与 SNMP 采集器共享调度循环；SNMP 采集器停顿不会阻塞 Syslog 接收。API 的 `/api/syslog/status` 提供收集器心跳和接收统计，`/api/syslog/events` 提供分页检索。

来源 IP 与 `devices.host` 精确相同时关联到设备。名称、主机名或消息内容不会自动建立设备关联；来源地址未知、经 NAT 或转发时保留为未匹配来源。删除设备后日志保留，设备关联置空。

## 源码 Compose 默认配置

| 环境变量 | 默认值 | 说明 |
| --- | ---: | --- |
| `SYSLOG_HOST_BIND` | `0.0.0.0` | Docker 宿主机绑定地址；可限制为管理网 IP |
| `SYSLOG_UDP_HOST_PORT` | `514` | 宿主机 UDP 端口，须与设备配置一致 |
| `SYSLOG_MAX_MESSAGE_BYTES` | `8192` | 单条日志最大保存字节数 |
| `SYSLOG_QUEUE_SIZE` | `5000` | 内存队列容量；数据库持续不可用时满队列会丢弃新日志 |
| `SYSLOG_BATCH_SIZE` | `200` | 一批写入条数，上限 1000 |
| `SYSLOG_FLUSH_INTERVAL_MS` | `500` | 批次写入最大等待时间 |
| `SYSLOG_RETENTION_DAYS` | `30` | 按接收时间保留天数 |

容器内监听 UDP 1514，Compose 映射至宿主机 UDP 514，容器以非 root 用户运行。部署到 Linux 主机时如 514 已被本机 Syslog 服务占用，可把 `SYSLOG_UDP_HOST_PORT` 改成空闲端口；设备端也必须同步配置该端口。Windows 离线部署支持这些参数，详见 [Windows 部署说明](../deploy/windows/部署说明.md)。

## 消息与搜索

- 优先按 RFC 5424 解析版本、时间、主机名、程序、进程 ID、消息 ID 和结构化数据；支持 RFC 3164 常见头部。格式异常时仍保存原文和来源 IP。
- 同时保存设备报告时间和平台接收时间；搜索、排序、保留策略使用平台接收时间。
- 严重级别按 Syslog 标准 0–7 保存。UI 的“严重”筛选合并 0–2，“错误”是 3，“警告”是 4，“通知/信息”是 5–7。
- 搜索消息、主机名、程序名、消息 ID 使用 PostgreSQL `simple` 全文索引；来源 IP 与已关联设备名称可单独筛选匹配。支持 1 小时、6 小时、24 小时、7 天以及不超过 31 天的自定义范围。
- CSV 导出当前页数据。默认每页 50 条，最大 200 条；页面可按设备、级别和时间筛选。

## 运维与限制

- 服务状态每 10 秒写入数据库；页面在最近 30 秒内收到心跳时显示接收正常。最近接收时间、已接收、已保存、队列丢弃数可帮助区分容器运行与数据抵达情况。
- 数据库异常时收集器保留内存中的待写批次并重试；队列有界，进程退出/主机断电、队列耗尽或 UDP 网络丢包都可能造成日志缺失。当前没有磁盘缓冲或 ACK。
- 当前只接收 UDP，没有 TCP/TLS、来源认证、设备厂商专属字段解析或基于日志的告警规则。请用网络边界/主机防火墙限制可信日志源，不要把 UDP 514 暴露给公网。
- 日志中可能包含账号、地址或配置片段，应按敏感运维数据保护。默认保留 30 天；高日志量部署应先评估数据库增长并调低保留期。删除按 5000 条分批执行。
- 事件暂不自动触发告警邮件；日志页面只显示接收和检索结果。后续可再设计可配置规则、抑制窗口和告警去重。
