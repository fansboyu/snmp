# 网络拓扑使用与部署说明

本次改动集中在拓扑页面、拓扑 API、邻居采集与存储，不替换设备详情、端口流量、告警或通知模块。

## 发现与状态

- LLDP/CDP 分协议记录成功、空结果、部分成功、失败和不支持。只有完整成功或明确空结果才将该协议未出现的旧邻居标为过期；超时、部分读取失败不会清空旧连接。
- 设备匹配优先使用人工确认、管理 IP、已知 chassis 标识和准确名称；名称冲突进入待确认列表。接口按 ifIndex 或标准化名称匹配，不能把其他设备的端口绑定到当前端点。
- 相同端点端口的双向 LLDP/CDP 证据合并为一条物理连接；不同端口的并行连接保留。未纳管邻居作为灰色节点，不会自动添加监控设备。
- 邻居证据超过 20 分钟显示过期，不等于物理断线。端口新鲜状态、管理停用状态和已确认设备离线共同决定链路状态；页面展示判定原因。设备状态沿用已有六分钟采集窗口和主动探测机制。

## 页面操作

v1.6.3 增加“发现诊断 / 立即采集”：展示发现进度与各设备协议原因，支持将单设备邻居请求加入采集器有界队列。请求状态保存在迁移 `009_topology_discovery_requests.sql` 新增的表中；同设备任务串行，重复提交复用活动请求，运行/排队超时可恢复。短名称匹配仅提供候选，需人工确认；Gi/Te 等端口缩写和设备内唯一 ifAlias 可参与匹配，不完整证据仅在共享已知端口且候选唯一时合并。

1. 默认进入查看模式，每 30 秒更新状态；后台标签页暂停刷新。刷新按节点和链路增量更新，保留坐标、缩放和选中项。
2. 点击节点查看设备状态，可跳转原设备详情；点击链路查看两端端口、流量、样本时间、邻居证据与相关告警，可跳转原端口详情。
3. 进入编辑模式后可添加节点、连接、删除选中内容，调整名称、层级、锁定位置和端口绑定。人工端口绑定不会被自动同步覆盖。删除自动连接会记录抑制项，避免下一次同步立即重新生成。
4. 自动布局先预览，点击保存才写入；锁定节点保持原位。未保存布局会暂停自动刷新，离开页面或退出编辑时提示处理。
5. 按设备分组或名称/IP 筛选。聚合关系由用户指定父连接和成员，支持折叠显示，不自动推断 LACP。父连接流量为成员参考端口速率之和，A/B 两端不会重复相加；成员数据缺失时不以零代替。
6. 变更记录保存节点、链路、端口绑定和聚合等配置变更，支持游标翻页；仅更新时间不会产生重复记录。当前记录没有操作者字段，也不替代独立的账号审计系统。

拓扑上的入/出方向均相对参考端口所在设备；两端流量可能受采样时间与丢包等影响而不同。图形连接本身不代表单向通信。无有效样本显示空状态，过期当前速率显示未知。

## 后台协作

采集器沿用设备独立调度，端口和标量继续按原周期采集，邻居使用独立低频任务。首次快速采集执行后即可安排邻居任务，不要求整台设备所有指标成功。任务预算同时覆盖采集和数据库写入。

API 每 30 秒检查邻居/人工确认变更并协调默认拓扑，也可在编辑模式手动同步。同步读取已有发现结果，不触发即时 SNMP 扫描。链路流量批量接口每次最多 100 条，前端按批读取；历史曲线复用原端口流量计算和降采样逻辑。历史记录超过 90 天后由 API 每小时分批清理，每批最多 5000 条。

## 数据库与接口

新增迁移 `008_topology_monitor.sql`：扩展节点层级、锁定和身份字段，链路物理标识、协议证据、人工绑定和聚合关系；新增 `topology_scans`、`topology_identities`、`topology_neighbor_bindings`、`topology_suppressed_links` 和 `topology_changes`。原监控数据与历史样本不删除。

沿用 `/api/topology` 旧入口，增加：

| 方法与路径 | 用途 |
| --- | --- |
| GET `/default/history?before=&limit=` | 变更记录，单页最多 100 |
| GET `/default/layout-preview` | 自动布局建议，不写入 |
| PATCH `/nodes/:id/settings` | 层级、锁定和名称 |
| PUT / DELETE `/neighbors/:id/binding` | 确认或清除邻居匹配 |
| PATCH `/links/:id/settings` | 两端接口、名称和聚合父链路 |
| GET `/links/:id/detail?range=1h` | 端口流量、证据、成员和告警 |
| POST `/default/traffic` | 按 `link_ids` 数组批量读取当前流量 |

## Docker 更新

先备份数据库及原部署配置，并沿用现有 Compose 项目名、环境变量和数据卷。不要执行 `down -v` 或初始化 seed 脚本。

```bash
docker compose build
docker compose run --interactive=false -T --rm --no-deps migrator
docker compose up -d
docker compose restart web-vue3
docker compose ps
curl --fail http://localhost:15173/health
```

迁移成功后再启动应用；本版 Go 服务共享初始化互斥逻辑，需要一起构建更新。重启 Web 可确保 Nginx 使用重建后 API 的容器地址。本次不增加运行容器，源码与标签随 v1.6.3 发布，旧离线发布包不覆盖。

验证范围包括匹配冲突、双向去重、并行链路、过期语义、协议失败保留、端口归属、聚合关系约束、锁定布局、重复同步、历史翻页，以及原设备健康与端口速率计算回归。隔离数据库中的模拟连接用于测试，不写入本机真实监控数据库。大规模设备容量和具体厂商 LLDP/CDP 行为仍需在客户网络验证。
