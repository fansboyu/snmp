# 网络设备配置备份

## 当前范围

当前实现提供 SSH 只读配置获取、定时/手动任务、版本留存、SHA-256 校验、差异比较和受控下载。首版不向设备写入任何命令或配置，也不提供恢复下发按钮。NETCONF 在适配器接口中预留，但当前会明确报告未实现；实际采集使用 SSH CLI。

现有 Go collector 中运行一个独立配置备份调度器，不增加常驻容器。它单独轮询配置备份队列，最多两个并发会话；SNMP 采集仍使用自己的设备调度。计划任务由数据库领取，支持跨进程 `SKIP LOCKED`、重启恢复和每任务最多三次退避重试。

## 支持命令模板

| 平台模板 | 关闭分页 | 读取命令 |
| --- | --- | --- |
| Cisco IOS | `terminal length 0` | `show running-config` |
| Huawei VRP | `screen-length 0 temporary` | `display current-configuration` |
| H3C Comware | `screen-length disable` | `display current-configuration` |

配置备份通过交互式 SSH CLI 执行，并等待设备提示符。使用设备维护账号的只读权限。当前不支持任意自定义命令模板、enable 密码二次提权、Telnet、SCP/SFTP、配置 startup-config 或厂商专有 API。

## 启用流程

1. 进入“配置备份”，选中设备并配置平台模板、SSH 端口和只读用户名。
2. 通过可信管理网或设备控制台取得 SSH 主机密钥指纹，核对后填写 `SHA256:...`。可在运维终端使用 `ssh-keyscan -p 22 设备地址 | ssh-keygen -lf -` 查看候选指纹，但必须通过设备控制台/可信资产记录核实；不能把扫描结果本身当作可信验证。
3. 保存 SSH 密码或私钥（二选一），设置自动周期及版本保留数。密码和私钥不会从 API 回传；再次保存时凭据字段留空会保留现有凭据。
4. 先点“立即备份”验证 SSH 连接、主机指纹和命令模板，再启用自动备份。失败原因显示在设备任务状态中；短暂错误最多重试三次。
5. 在“历史版本”比较脱敏差异，或确认下载提示后取回原始配置文件。

默认保留每台设备最近 30 个成功版本，可设 2–365 个。单份配置上限为 5 MiB；较大的配置会失败并保留诊断状态，不截断保存。备份成功后记录 SHA-256 与大小；完全相同的内容仍保留一次版本记录并标为无变化。

## 存储和密钥

- 迁移 `015_device_config_backups.sql` 创建设备配置、任务、加密版本和下载/差异审计表。API 与采集器必须使用同一个 `JWT_SECRET`；当前复用该密钥派生 AES-256-GCM 密钥。
- SSH 凭据和配置正文在写入数据库前加密。保留 JWT_SECRET、PostgreSQL 备份和数据卷备份；如果 JWT_SECRET 丢失/更换，已存密文无法解密。修改密钥前需先设计密钥轮换和重新加密流程。
- 差异页面会对含 `password`、`secret`、`community`、预共享密钥等关键字的整行脱敏，但原始配置为灾难恢复需要仍完整保存在加密密文中。下载后文件是明文，必须保存到访问受控的位置；下载和查看差异会记录账号、设备、版本与时间。
- 数据库负责承载加密配置内容，版本数上限用于控制体积。当前单文件 5 MiB；大规模部署若备份量明显增加，再考虑迁移到加密对象存储或独立文件存储。

## 已知边界

- 自动备份依赖设备支持 SSH、设备管理网络可达、命令权限足够，以及正确的主机指纹。主机 SSH 密钥轮换后需人工更新 pin。
- 设备 CLI 提示符和输出格式有厂商/软件版本差异。遇到分页符、提示符不匹配或非预期 banner 时会任务失败，不会将不完整输出记为成功版本。
- 暂无行级跨厂商规范化；时间戳、自动生成计数或设备重启信息可能产生差异。恢复时仍需由网络工程师审阅配置并在设备侧执行。
- 单管理员角色体系下审计记录当前只有用户名；细粒度 RBAC、外部 KMS/密钥轮换、NETCONF、恢复操作与双人审批未纳入首版。
