# netlooker Windows 离线发布包

本包包含当前项目的邮件配置、端口详情、设备独立调度、新版 Logo，以及设备页“原位三列”关注端口卡片。发布版本以 `VERSION.json` 为准；镜像、迁移文件和运行脚本均带校验值。程序版本为 RELEASE_VERSION，VERSION.json 记录数据库主版本、构建对应的 Git 提交及镜像 ID。当前模板使用 PostgreSQL 18，历史 v1.6.0 发布包继续使用 PostgreSQL 16。

## 能否复制到其他电脑直接离线运行

可以在准备好 Docker 环境的 Windows x64 电脑上离线部署。本包已经包含全部七个运行镜像，不需要下载镜像、安装 Go/Node.js 或编译源码。

目标电脑需要提前具备：

- 支持 Docker Desktop 的 Windows 11 x64，启用硬件虚拟化。
- 安装并启动 Docker Desktop，切换到 Linux containers；WSL 2 环境可由 Docker Desktop 使用，无需额外安装 Ubuntu。
- Docker Compose 2.20 及以上。本包脚本兼容 Windows PowerShell 5.1 和 PowerShell 7。
- 磁盘留出镜像、数据库和备份空间；历史样本增长需要按规模规划。

Docker Desktop 和 WSL 安装程序未包含在本包内。如果目标电脑从未准备过这些环境，需要预先下载官方安装程序，在离线现场安装、启用相关 Windows 功能并按要求重启。准备环境的官方说明：https://docs.docker.com/desktop/setup/install/windows-install/ 。Windows Server 请采用 Linux 虚拟机部署，本包不提供 Docker Desktop 的 Windows Server 安装方案。

没有公网时网页、数据库、采集器可以运行；设备采集需要局域网访问目标 SNMP 地址及 UDP 端口，邮件需要能访问配置的 SMTP 服务。未连接任何网络时可以查看本机已保存数据，不能采集远端设备。

## 首次安装

1. 把 ZIP 复制到目标电脑，解压到本地目录，例如 `D:\Netlooker\netlooker-RELEASE_VERSION-windows-amd64`。整个目录保留，包含 `images.tar`、`postgres` 和脚本。
2. 启动 Docker Desktop，等待引擎 ready。
3. 在该目录打开 PowerShell，执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\install.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\status.ps1
```

安装会校验文件、加载本地镜像，首次生成 `.env`，随机生成数据库密码、管理员初始密码和 JWT 密钥。已有 `.env` 不会被覆盖。重复加载镜像不删除数据库；如果镜像已加载，可使用 `install.ps1 -SkipImageLoad`。

浏览器访问 `http://localhost:15173`。初始用户名默认为 `admin`，初始密码读取本目录 `.env` 中 `ADMIN_PASSWORD`，不会打印到日志。登录后可修改密码；此时数据库中的密码为准，`.env` 中仍是首次初始化值。

只开放网页端口，PostgreSQL 和 API 没有发布宿主机端口。其他局域网电脑访问 `http://部署电脑IP:15173`；如需放行 Windows 防火墙，仅放行可信网络的 TCP 15173。本包不会自动更改防火墙。

## 配置和数据持久化

- 关注端口记录保存在各自浏览器中，不包含在数据库备份内；当前不提供跨电脑的账号收藏同步。

- `.env` 包含密码和密钥，应限制读取权限，不要随意发送给他人。
- `COMPOSE_PROJECT_NAME=netlooker` 是数据卷身份，移动目录、升级程序时必须保留这个值。
- `WEB_PORT` 可修改；`WEB_ORIGIN` 对应实际网页访问地址。`HOST_BIND` 默认 `0.0.0.0`，仅本机访问可改为 `127.0.0.1`。
- 当前 PostgreSQL 18 部署模板的数据保存在 Docker volume `netlooker_postgres18-data`，不在镜像里。旧 PostgreSQL 16 包使用 `netlooker_postgres-data`。停止容器、替换发布目录不会自动迁移数据库到另一台电脑。
- 数据库密码首次建库后不可只修改 `.env`：数据库角色密码也必须同步更新，否则应用无法连接。
- 常驻容器配置 `unless-stopped`，日志轮转为每服务 10MB × 3。手动运行 stop.ps1 后，需要再次运行 start.ps1。
- Windows 重启后需确保 Docker Desktop 实际运行。容器重启策略不能启动 Docker Desktop；建议启用 Desktop 登录后自动启动，并实测整机重启恢复。无人登录的长期服务优先使用 Linux 虚拟机/服务器。

## 停止与查看

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\stop.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\status.ps1
```

停止保留数据库卷。`status.ps1` 在系统未启动或健康检查失败时返回错误。日常可执行 `docker compose --env-file .env -f compose.yaml logs --tail=100 collector-go` 查看采集日志。不要运行 `docker compose down -v`，该操作会删除数据库卷。

## 备份

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\backup.ps1
```

备份生成 `backups/时间戳-随机后缀/`，包含：

- `database.dump`：PostgreSQL 一致性逻辑备份，包含设备、样本、模板、账号、邮件配置、告警等。
- `config.env`：原运行配置，包含 JWT 密钥，恢复邮件密码解密所必需。
- `backup.json`：版本信息和文件校验值。

采用容器内 pg_dump 和 docker cp，不经 PowerShell 文本管道传输二进制数据。备份应复制到另一块磁盘，整目录按敏感数据保管。运行中的备份是数据库快照，备份之后产生的数据不会包含其中。

## 恢复到另一台电脑

先在新电脑完成 install.ps1 和 start.ps1，再复制备份目录并执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\restore.ps1 -BackupDirectory D:\NetlookerBackup\20261007-120000-abcdef
```

脚本显示目标项目和数据库，要求输入 `RESTORE`。确认后停止应用写入，自动备份目标现有数据库，再在单一事务中替换数据库内容。失败时事务回滚，应用保持停止以便检查。

成功后保留目标电脑的项目名、端口、数据库密码；仅恢复源系统 JWT 密钥，保证原邮件密码可以解密。登录使用备份系统的账号及当时实际密码。邮件队列、发现任务也在数据库备份中；恢复后先确认这些任务符合新环境要求，再执行 start.ps1。避免两台主机同时对同一批设备工作或重复处理旧通知。

脚本提供 `-Force` 给明确知道目标数据库的自动化操作，跳过交互确认，仍执行自动安全备份。手工操作建议保留确认。

## 从当前开发项目迁移

此程序包不包含当前电脑的生产数据和开发 `.env`。原开发环境使用自己的 Compose 项目和固定数据库密码，不能直接把发布包 backup.ps1 放在开发目录运行。

可在原项目中执行：

```powershell
docker compose exec -T postgres pg_dump -U snmp -d snmp_monitor --format=custom --file=/tmp/netlooker-migration.dump
docker cp snmp-monitor-postgres:/tmp/netlooker-migration.dump D:\NetlookerBackup\database.dump
docker compose exec -T postgres rm -f /tmp/netlooker-migration.dump
```

同时保存原 `.env` 中实际的 JWT_SECRET。如果未显式设置，当前开发 Compose 使用 `snmp-monitor-dev-secret` 默认值。该密钥必须与备份数据库对应。保存到私密文件 `D:\NetlookerBackup\source.env`，其中必须显式包含 `JWT_SECRET=原系统实际密钥`。发布目录提供 import-backup.ps1 将 dump 和该配置转为带校验值的标准恢复包：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\import-backup.ps1 -DumpFile D:\NetlookerBackup\database.dump -SourceConfig D:\NetlookerBackup\source.env -OutputDirectory D:\NetlookerBackup\converted
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\restore.ps1 -BackupDirectory D:\NetlookerBackup\converted
```

该导入工具支持当前项目的 PostgreSQL 16/18 custom-format 备份，通过本包的 PostgreSQL 18 pg_restore 读取归档中的来源及工具版本，不会读取或改动正在运行的原数据库。导入需要 Docker 及已加载的本包数据库镜像。

## 升级及回退

以下常规升级流程适用于已经使用 PostgreSQL 18 的环境。旧 PostgreSQL 16 包升级到本模板时必须先迁移数据：暂停旧环境应用写入，在旧目录执行 backup.ps1，再停止旧容器（保留数据卷）；新包保留原项目名、密码和 JWT_SECRET，安装并启动新数据库后执行 restore.ps1 导入旧备份，最后 start.ps1。新卷名为 postgres18-data，旧 postgres-data 不会自动导入；只改 IMAGE_VERSION 会启动空数据库。启动验收前暂停正常采集，核对数据后再恢复。PostgreSQL 18 的默认 PGDATA 为 /var/lib/postgresql/18/docker。

1. 在旧发布目录执行 backup.ps1，并保存备份。
2. 解压新版本到另一目录，将旧 `.env` 复制过去，仅把 `IMAGE_VERSION` 更新为新包 VERSION.json 的 version；项目名、数据库密码、JWT_SECRET 保留。
3. 运行新包 install.ps1，再运行 start.ps1。脚本暂停应用写入后执行数据库迁移，迁移失败不会启动应用。
4. 确认登录、设备和端口采集正常，再保管旧版本与备份。

固定项目名和相同卷名使同一数据库主版本的新发布目录继续使用原数据卷。16→18 使用不同卷名，必须显式恢复。切换后 18 产生的新数据不会出现在旧 16 卷中；不能用 16 镜像启动 18 数据卷，也不承诺 18 备份可以反向恢复到 16。保管旧包、旧卷和迁移前备份。

## 内容清单

`images.tar` 包含 PostgreSQL、API、前端、采集器、发现服务、邮件服务、迁移工具。compose.yaml 无 build，所有镜像 pull_policy=never，启动脚本也指定 --pull never。VERSION.json 列出镜像 ID、源码基础提交、是否包含工作区改动及文件 SHA256。外层 ZIP 的校验值保存在同名 `.zip.sha256` 文件。
